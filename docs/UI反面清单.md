# UI 反面清单：这些做法在这个项目里是错的

> 配套文件：`UI设计需求文档.md`
> **这份比需求文档更重要。** 大部分外包设计失败不是因为能力不够，是因为做成了「正确的错误设计」。

---

## 一、这是什么类型的软件

```
这是**生产工具**，不是消费级App。

用户在用的时候：
- 站着
- 手上有事
- 客人正等着
- 每秒都在产生成本（客人在排队）

所以任何让界面「更呼吸」「更优雅」「更留白」的设计，
在这个场景里都是**制造等待**。
```

**判断标准**：如果一个设计决策让界面「更好看」但「要点更多次」或「要多看一眼」，**它是错的**。

---

## 二、明确禁止（Critical）

### 2.1 禁止：大留白

```
❌ 首屏大量空白
❌ 按钮之间 32px+ 间距
❌ 一屏只放 6 个商品卡

收银员要的是「一屏看全所有菜」，不是「一屏看 6 个菜然后滚动」。
```

### 2.2 禁止：装饰性元素

```
❌ 渐变背景
❌ 玻璃拟态 / 磨砂
❌ 发光 / 霓虹
❌ 阴影很重
❌ 圆角 ≥ 16px
❌ 插画 / 渐变插画头图
❌ emoji 当图标
```

**原因**：界面本身信息密度已经很高，装饰只会抢注意力、弱化信息层级。

### 2.3 禁止：营销页套路

```
❌ 首屏大标题 + 大副标题 + CTA 按钮
❌ "01 · 介绍" 编号眉标
❌ 每个区块上方一个加字距的大写英文标签
❌ "Scroll to explore" 滚动提示
❌ 卡片阴影模拟投影
```

**这一套是给落地页的，不是给收银台的。**

### 2.4 禁止：纯图标按钮

```
❌ 只有图标没有文字的操作按钮（除非是 100% 通用图标：关闭、返回、更多）

理由：员工流动快，新人靠认字不靠认图标。
```

### 2.5 禁止：隐藏关键信息在交互里

```
❌ 桌号要鼠标悬停才显示
❌ 订单金额要点进去才看到
❌ 沽清的菜要悬停才显示状态

收银台不能靠"悬停"获取信息。
```

## 三、必须做（这些是底线）

### 3.1 点击目标

```
主要操作按钮高度 ≥ 44px
可点区域 ≥ 44×44px

理由：可能用触控屏，可能手上有油，可能单手操作。
44px 是触控建议的最小值，不要用 32px 的紧凑按钮做主要操作。
```

### 3.2 数字可读性

```
金额、数量、桌号：使用等宽数字（tabular-nums）
金额：右对齐，同一列宽度一致
大金额（如找零）：字号 ≥ 32px

理由：收银员要快速比对「收了 100 找 30」对不对。
对齐不一致的数字列，扫视速度会明显下降。
```

### 3.3 状态必须配色 + 文字

```
❌ 只用红色表示错误但没有文字
✅ 红色 + 「网络异常」文字

桌台状态就是典型例子：
❌ 一块蓝的、一块绿的、一块黄的（只有颜色）
✅ 「空闲」「用餐中」「已预订」文字 + 颜色

色盲用户约占男性 8%，老板年纪大，认字比认色可靠。
```

### 3.4 空状态

```
必须有，且必须**有引导动作**

❌ "暂无数据"
✅ "还没有商品，去添加第一个商品 →"

理由：商家装好系统的第一眼看到的就是空状态。
"暂无数据"会让老板以为系统坏了。
```

## 四、收银台特有要求

### 4.1 主流程的每一步都要可回退

```
开台 → 点菜 → 收银

每个环节都要有明确的退出/返回路径，且不丢数据。
收银员中途被叫走（接电话、客人有问题），回来要能接着干。
```

### 4.2 破坏性操作要二次确认

```
清台、退单、反结账、强制关班、批量沽清
→ 必须确认，且确认框要写清「会影响什么」

❌ "确定吗？"
✅ "清台后 A01 桌的订单将被清空，无法恢复"
```

### 4.3 防重复提交

```
收银点「结账」可能连点两下（着急 + 鼠标不灵敏）
→ 按钮提交后立即禁用
→ 提交中要有明确状态
→ 重复提交要幂等（不能收两次钱）
```

### 4.4 数字输入

```
金额、数量输入框：
- 需要数字键盘（如果是触摸屏）
- 需要步进按钮（+ / -）或者可以直接点
- 称重商品要能输入小数
```

## 五、对标美团收银时的注意事项

```
✅ 逐屏对比功能清单，确认没漏功能
✅ 对比操作路径长度：我们点几下才能开台结账
✅ 对比信息密度：我们是不是比它少显示了关键信息

⚠️ 不要照抄它的视觉，要检查：
   - 它是给触屏设计还是鼠标？（我们是鼠标为主）
   - 它的留白适合他们的硬件吗？（我们可能分辨率更低）
   - 它有没有我们没有的复杂功能？不要为了对齐而加无用功能
```

## 六、快速自检清单

出稿前自查，每一条都要能回答「是」：

```
□ 1366×768 下主流程六屏信息完整，没有需要横向滚动的
□ 点单页一屏能看到 ≥ 12 个商品（按我们真实的分类密度）
□ 主要按钮都 ≥ 44px 高
□ 金额列右对齐，等宽数字
□ 每个界面都有空状态设计，且空状态有引导动作
□ 每个界面都有加载中、错误、离线状态
□ 状态不只靠颜色区分，都有文字
□ 破坏性操作都有二次确认，且确认文案说清后果
□ 没有渐变、没有玻璃拟态、没有大圆角
□ 没有 emoji 当图标
□ 操作按钮都有文字标签
□ 关键信息不需要悬停才能看到
□ 组件规范里定义了所有用到的状态（按钮有 4 个状态，不只 2 个）
```

## 七、什么该问我们

**遇到这些情况请直接问，不要猜：**

```
□ 真实门店里，这个操作一天发生多少次？
□ 商家现在的电脑是什么配置？
□ 这两个功能冲突时，商家会要哪个？
□ 这个信息老板会看吗？还是只有收银员看？
□ 有没有更简单的做法能达到同样效果？
```

**特别是最后一条。** 如果一个功能可以用更简单的界面表达，**请说出来**，
不要因为"功能应该更丰富"而加复杂度。
