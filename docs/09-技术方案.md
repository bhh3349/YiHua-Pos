# 逸华餐饮收银 —— 技术方案

> 目标：一套代码同时交付 **Linux 收银镜像**（主力，触屏一体机）
> 与 **Windows 收银端**（台式机，Win10+）；
> 满足「4GB 内存 / 低功耗 CPU / 机械硬盘」的性能约束。

---

## 0. 目标平台策略（**重要前提**）

| 设备类型 | 系统 | 优先级 | 说明 |
|---|---|---|---|
| **触屏收银一体机**（低配） | **Linux 镜像** | ⭐ **主力** | 直接刷镜像，开箱即用；无授权成本、免维护 |
| 台式收银机 | Windows 10+ | 次要 | 商家已有 Windows 环境，出安装包 |

**结论**：
- **单目标框架 `net8.0`**，不做 .NET Framework 分支
- 一套代码，两个 RID：`linux-x64`（主力）+ `win-x64`
- 不需要考虑 Windows 7

---

## 1. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| **客户端框架** | **.NET 8 + Avalonia UI 11** | 一套代码出 Linux + Windows；XAML 语法接近 WPF，可迁移行业通行的 427 个视图 |
| **客户端架构** | Prism + DryIoc（与行业通行做法一致） | 模块化、依赖注入、区域导航 |
| **本地数据库** | SQLite + SqlSugar | 行业通行做法同款；单文件、免安装、WAL 支持 |
| **服务端** | FastAPI + SQLAlchemy（已实现） | 轻量、开发快、部署简单 |
| **服务端数据库** | MySQL 8（生产）/ SQLite（开发） | 已支持一键切换 |
| **反向代理** | Nginx | TLS + 静态资源 |
| **部署** | Docker Compose / systemd | 已提供 |
| **实时通道** | MQTT（二期） | 云打印 / 叫号 / 多端同步 |

### 1.1 为什么不选其他方案

| 方案 | 否决原因 |
|---|---|
| WPF (.NET) | **Windows-only**，出不了 Linux 版，而 Linux 是我们的主力平台 |
| Electron / Tauri | 内存 300-500MB，4GB 一体机吃力；外设桥接复杂 |
| Qt / C++ | 开发效率低（AI 协作 C# 效率高得多）；Linux 上确实更原生，但代价不划算 |
| Flutter | Linux 桌面支持弱，串口/USB 桥接麻烦 |
| 纯 Web | 收银机不能依赖浏览器，外设无法访问 |

## 3. 外设兼容方案（**重点**）

### 3.1 为什么打印机可以「随便切换」

国内小票打印机 **99% 兼容 ESC/POS 指令集**（爱普生制定的标准）。所以：

```
不需要厂商驱动  →  只要能往设备发字节，就能打印
```

支持的四条通路：

| 通路 | 实现方式 | 适用 |
|---|---|---|
| USB | Windows: WinUSB/打印类驱动；Linux: libusb / `/dev/usb/lp*` | 最常用 |
| 串口 | RS232 / TTL，直接读写 | 一体机内置 |
| 网口 | TCP 9100 端口直发 | 后厨打印机 |
| 蓝牙 | SPP 虚拟串口 | 便携设备 |

**所以我们只需要实现 ESC/POS 指令生成器**，不需要适配每个品牌。

### 3.2 可复用资产

| 资产 | 复用价值 |
|---|---|---|
| ESC/POS 指令集 | `Printer.Template.Command.EscPosCommand` / `EscPosInstruction` | ★★★★★ 直接移植 |
| 打印模板引擎 | `Printer.Template.Receipt.*` | ★★★★★ |
| 打印机实例（USB/网口/串口/LPT/云） | `Printer.Template.Receipt.Instance.*` | ★★★★ |
| 标签打印（TSPL/CPCL） | `Printer.Template.Receipt.LabelContentParse` | ★★★★ |
| **20+ 品牌电子秤协议** | `HardwareDevice.EleScale.Contract.*` | ★★★★★ |
| 电子秤管理器 | `HardwareDevice.EleScale.ScaleManager` | ★★★★ |

## 4. 离线方案（**核心**）

### 4.1 本地优先架构

```
                     ┌─────────────────────┐
   用户操作 ────────→ │  本地 SQLite（权威）  │ ←── 断网时唯一数据源
                     └──────────┬──────────┘
                                │ 写入 outbox
                                ▼
                     ┌─────────────────────┐
                     │  outbox 队列         │
                     │  (clientOrderNo 唯一)│
                     └──────────┬──────────┘
                                │ 后台线程顺序发送
                                ▼
                     ┌─────────────────────┐
                     │  服务端（幂等去重）    │
                     └─────────────────────┘
```

### 4.2 outbox 表设计

```sql
CREATE TABLE outbox (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    client_order_no   TEXT NOT NULL UNIQUE,   -- 幂等键
    api_path          TEXT NOT NULL,
    payload_json      TEXT NOT NULL,
    status            INTEGER DEFAULT 0,      -- 0待发 1成功 2失败
    retry_count       INTEGER DEFAULT 0,
    last_error        TEXT,
    created_at        TEXT,
    sent_at           TEXT
);
```

**规则**：
1. 结账成功立刻写 outbox 并返回成功（**收银不被网络阻塞**）
2. 后台线程按 `created_at` 顺序发送
3. 失败重试（指数退避，最多 N 次）
4. 服务端返回 `409`（已存在）视为成功
5. 网络恢复后自动重试全部待发

### 4.3 断网可用的功能

| 功能 | 断网 | 说明 |
|---|---|---|
| 点单 / 购物车 | ✅ | 纯本地 |
| 结账（现金/记账） | ✅ | 写本地 + outbox |
| 打印 | ✅ | 本地指令 |
| 称重 | ✅ | 串口 |
| 交班 | ✅ | 本地记账 |
| 商品浏览 | ✅ | 本地快照 |
| 桌台 | ✅ | 本地表 |
| 会员 | ❌ | 需要云端 |
| 团购核销 | ❌ | 需要云端 |
| 报表 | ⚠️ | 本地基础汇总可用 |

## 5. 体积与性能优化（**针对老设备**）

### 5.1 体积目标：970MB → 250MB

行业通行的 970MB 构成与优化空间：

| 项 | 当前 | 优化后 | 手段 |
|---|---|---|---|
| `runtimes/` 跨平台 native 库 | 347 MB | **~30 MB** | **只保留 `win-x64` / `linux-x64`**，删掉 osx/ios/tvos/freebsd/linux-mips64 等 |
| CEF 内嵌浏览器 | 188 MB | **0** | 团购核销走 API，不需要浏览器 |
| .NET 运行时 | 139 MB | 139 MB | 必需（或改框架依赖模式减到 ~5MB） |
| WPF/Avalonia 资源 | 75 MB | **~30 MB** | 图片压缩（WebP）、去掉不用的 |
| 语音 / ONNX | 70 MB | **0** | 一期不做语音播报 |
| 多语言资源 | 53 MB | **~2 MB** | 只留 `zh-Hans` |
| 数据库驱动 | 23 MB | **~2 MB** | 只留 SQLite |
| 业务模块 | 18 MB | 18 MB | |
| **合计** | **970 MB** | **~220 MB** | |

> **最重要的优化**：`runtimes/` 目录里 347MB 全是 NuGet 包自动带进来的**全平台** native 库，
> 对 x64 收银机 100% 是垃圾。构建时用 `RuntimeIdentifier` 过滤即可。

### 5.2 启动优化（目标 ≤ 8 秒）

| 手段 | 收益 |
|---|---|
| 模块延迟加载（Prism `OnDemand`） | 大 |
| 启动时**不做同步网络请求** | 大 |
| XAML 预编译（Avalonia XAML 编译进 DLL） | 中 |
| 首屏只加载首页所需数据 | 中 |
| 数据库索引优化 | 小 |
| 禁用不必要的动画 | 小 |

### 5.3 内存优化（目标 ≤ 300MB）

| 手段 | 收益 |
|---|---|
| 去掉 CEF | 省 100-200MB |
| 图片按需加载 + 缓存上限 | 中 |
| 商品列表虚拟化（UI 虚拟化） | 中 |
| 及时释放打印/秤的流 | 小 |

## 6. Linux 收银镜像方案

### 6.1 镜像设计

```
┌────────────────────────────────────────┐
│ 分区布局（A/B 双系统）                    │
├────────────────────────────────────────┤
│ /boot          FAT32   256MB            │
│ rootfs-A       ext4    2GB   ← 系统 A   │
│ rootfs-B       ext4    2GB   ← 系统 B   │
│ data           ext4    剩余   ← 业务数据 │
└────────────────────────────────────────┘
```

| 特性 | 实现 |
|---|---|
| 基础系统 | Debian 12 minimal（~400MB） |
| 图形栈 | Wayland（Weston）或最小 X11 |
| 桌面环境 | **无**（直接全屏应用） |
| 根文件系统 | **只读** + overlayfs（写操作重定向到 tmpfs/data 分区） |
| 启动 | systemd → 自动登录 → 启动收银应用（kiosk 全屏） |
| 升级 | A/B 分区，新版本写入空闲分区 → 切换启动项 → 失败自动回滚 |
| 配置持久化 | `/data` 分区（业务数据库 + 配置） |
| 远程管理 | SSH（可选关闭）+ 自研升级服务 |

### 6.2 启动流程

```
BIOS → GRUB → systemd
  ├── 挂载只读 rootfs
  ├── 挂载 data 分区
  ├── 启动串口/网络
  └── 启动 pos-client.service
        └── Avalonia 应用全屏启动
              └── 显示收银界面（目标 ≤ 20 秒）
```

### 6.3 交付方式

| 方式 | 说明 |
|---|---|
| **U 盘刷机** | 制作可启动 U 盘，插上自动安装到目标硬盘 |
| **整机出货** | 预装好镜像的工控机/一体机直接发货 |
| **PXE 网络安装** | 批量部署（多店场景） |

## 10. 关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **一体机能否装 Linux** | 主力交付受阻 | 优先选已验证的工控机型号；BIOS 关闭 Secure Boot；提前拿真机验证 |
| **触摸屏驱动** | 无法操作 | 多数走 USB HID / I2C，内核自带；个别型号需额外驱动，选型时验证 |
| **外设权限（udev）** | 应用访问不了 USB/串口 | 镜像里预置 udev 规则 + 用户组，随镜像分发 |
| Avalonia XAML 迁移量比预期大 | 工期 | 先迁移 3 个核心视图验证，再批量 |
| 某些外设协议不兼容 | 客户现场 | 优先支持主流品牌；留扩展接口 |
| 老设备显卡驱动 | 显示异常 | 优先 Intel/AMD 集显；备选 fbdev |
| 老设备性能不达标 | 体验 | 体积/内存优化 + 延迟加载 + 技术验证原型先行 |
| AI 协作的代码质量 | 可维护性 | 强制单元测试 + 代码规范 + 每个任务有验收标准 |

### 10.1 已排除的风险

| 风险 | 为什么不存在 |
|---|---|
| Windows 7 兼容 | **低配一体机走 Linux，台式机走 Win10+，不考虑 Win7** |
| .NET Framework 分支维护 | 单目标 `net8.0`，不需要 net48 |
| 刷脸设备 | 已确认餐饮商家不用 |
