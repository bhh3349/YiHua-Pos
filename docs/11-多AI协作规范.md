# 逸华餐饮收银 —— 多 AI 协作开发规范

> 本文档解决一个核心问题：**多个 AI 并行开发时如何不撞车**。
> 适用：1 个 Lead（DeepSeek Harness）+ 4 个 Worker（3× MUSE + 1× Hermes）

---

## 1. 开发方式声明（先明确这个）

**本项目是「参考实现 + 自主开发」，不是照抄。**

| 资产 | 处理方式 | 禁止事项 |
|---|---|---|
| **协议层**（ESC/POS 指令、电子秤串口协议） | 参照协议规范自己实现 | ❌ 不逐行复制反编译代码 |
| **业务逻辑**（订单流转、桌台、交班） | 读懂流程，按自己的架构实现 | ❌ 不复制类名/方法名/结构 |
| **UI**（427 个 XAML） | **当设计稿看**，自己重画 | ❌ 不直接复制 XAML |
| **接口契约**（52 个真实接口） | 照着实现（协议事实） | ✅ 允许 |
| **反编译 C# 源码** | **只看不抄** | ❌ 禁止复制 |

**判断标准**：如果你写的代码和反编译源码**逐行相似**，就是抄；如果是**同样的功能、不同的实现**，就是参考。

## 2. 防撞车三原则

### 原则一：目录独占（最重要）

**一个任务 = 一个目录 = 一个 Owner**。任何时刻，一个目录只能有一个 AI 在写。

```
✅ 正确
   MUSE-1 写  src/YiHua.Pos.Hardware/Printing/EscPos/**
   MUSE-2 写  src/YiHua.Pos.Hardware/Scales/**

❌ 错误
   MUSE-1 和 MUSE-2 同时改 src/YiHua.Pos.Hardware/Hardware.csproj
```

### 原则二：一个模块 = 一个项目

每个业务模块是**独立的 .csproj**，这样连项目文件都不会撞。

```
src/Modules/
├── YiHua.Pos.Modules.Login/          ← T-301 独占
├── YiHua.Pos.Modules.Product/        ← T-302 独占
├── YiHua.Pos.Modules.Desk/           ← T-306 独占
├── YiHua.Pos.Modules.OrderMeal/      ← T-303 独占
├── YiHua.Pos.Modules.OrderMeal.Fast/ ← T-304 独占
├── YiHua.Pos.Modules.Pay/            ← T-307 独占
├── YiHua.Pos.Modules.Order/          ← T-308 独占
├── YiHua.Pos.Modules.Shift/          ← T-309 独占
├── YiHua.Pos.Modules.Report/         ← T-310 独占
└── YiHua.Pos.Modules.Settings/       ← T-311 独占
```

### 原则三：公共文件只有 Lead 能改

以下文件**冻结**，Worker 只能读不能写。需要改动时，向 Lead 提「接口变更请求」。

| 冻结文件 | 内容 |
|---|---|
| `YiHua.Pos.sln` | 解决方案 |
| `Directory.Build.props` | 全局构建配置 |
| `src/YiHua.Pos.Domain/**` | 领域实体与枚举 |
| `src/YiHua.Pos.Hardware/Abstractions/**` | 硬件接口 |
| `src/YiHua.Pos.Services/Abstractions/**` | 服务接口 |
| `src/YiHua.Pos.UI/Themes/Tokens.axaml` | 设计 Token |
| `src/YiHua.Pos.App/App.axaml.cs` | 依赖注入注册（Lead 合并） |

## 5.5 Git 分支协作（**能 push 的 AI 用这套**）

### 分支模型

```
main                       ← 只接受「验证通过」的代码（Lead 合并）
├── task/T-102-escpos      ← MUSE-1
├── task/T-105-scales      ← MUSE-2
├── task/T-003-data        ← MUSE-3
└── task/T-201-server      ← Hermes
```

**核心规则：谁都不许直接推 main。**

### Worker 操作流程

```bash
# 1. 克隆（首次）
git clone https://github.com/bhh3349/YiHua-Pos.git
cd YiHua-Pos

# 2. 建自己的分支
git checkout -b task/T-102-escpos

# 3. 开发（只改自己独占目录）

# 4. 提交前先同步 main（避免落后）
git fetch origin
git rebase origin/main

# 5. 提交并推送
git add -A
git commit -m "T-102: 实现 ESC/POS 指令生成器"
git push -u origin task/T-102-escpos

# 6. 通知 Lead：「T-102 完成，分支 task/T-102-escpos」
```

### 分支命名规范

| 任务号 | 分支名 |
|---|---|
| T-102 | `task/T-102-escpos` |
| T-105 | `task/T-105-scales` |
| T-003 | `task/T-003-data` |
| T-201 | `task/T-201-server` |

### Lead 集成流程

```bash
git fetch origin
git checkout task/T-102-escpos

# 1. 越界检查：看有没有改别人的目录
git diff --name-only origin/main...HEAD

# 2. 全量编译 + 测试
dotnet build client/YiHua.Pos.sln
dotnet test  client/YiHua.Pos.sln

# 3. 通过 → 合并
git checkout main
git merge --no-ff task/T-102-escpos -m "合并 T-102：ESC/POS 指令生成器"
git push origin main

# 4. 不通过 → 打回，附具体错误
```

### 冲突处理

| 情况 | 处理 |
|---|---|
| `git push` 被拒（非快进） | `git fetch origin && git rebase origin/main` 后重推 |
| rebase 有冲突 | **停下来**，把冲突文件告诉 Lead，不要自己瞎合并 |
| 发现自己改了别人的目录 | `git checkout origin/main -- <别人的文件>` 还原 |

### 为什么不能直接推 main

| 风险 | 后果 |
|---|---|
| 推了编译不过的代码 | 其他人的构建全挂 |
| 两人同时推 | 后者被拒，处理不当会丢代码 |
| 推了越界修改 | 覆盖别人正在进行的工作 |
| 出了问题 | 无法单独回滚某一个任务 |

**走分支的话，每一个任务都是独立的、可回滚的。**

## 6. 集成流程（Lead 负责）

```
Wave N 开始
  ↓
各 Worker 并行开发（只改自己目录）
  ↓
Worker 完成 → 提交「改动清单 + 测试输出」
  ↓
Lead 执行集成检查：
  1. git status —— 检查有没有越界修改
  2. dotnet build —— 全量编译
  3. dotnet test —— 全量测试
  4. 检查冻结文件是否被改
  ↓
通过 → 合并，进入 Wave N+1
不通过 → 打回，附具体错误
```

### 集成检查脚本（Lead 用）

```powershell
# 1. 检查越界修改
git status --short

# 2. 检查冻结文件是否被改动
git diff --name-only | Select-String -Pattern "Domain/|Abstractions/|Tokens.axaml|Directory.Build.props|\.sln"

# 3. 全量编译
dotnet build YiHua.Pos.sln

# 4. 全量测试
dotnet test YiHua.Pos.sln
```

## 7. 冲突处理流程

| 情况 | 处理 |
|---|---|
| Worker 需要改公共接口 | 提「接口变更请求」给 Lead，**不要自己改** |
| 两个 Worker 改了同一文件 | Lead 判定归属，回滚其中一个 |
| Worker 发现接口设计有问题 | 提给 Lead，由 Lead 统一修改后通知全员 |
| Worker 需要另一个 Worker 的代码 | 通过 Lead 协调，或等对方 Wave 完成 |

### 接口变更请求格式

```markdown
【变更请求】ICR-001
【提出者】MUSE-2
【需要改的文件】src/YiHua.Pos.Hardware/Abstractions/HardwareAbstractions.cs
【变更内容】IScale 增加一个方法：Task<int> GetBaudRateAsync();
【原因】凯士电子秤需要运行时探测波特率
【影响范围】所有 IScale 实现（MUSE-2 自己会改）
```
