# 构建与发布

> 本文档记录发布配置、体积目标、以及踩过的坑。

---

## 1. 发布模式与体积

实测结果（骨架版本，业务模块加入后会增大）：

| 目标平台 | 模式 | 体积 | 用途 |
|---|---|---|---|
| **linux-x64** | **框架依赖** | **22.7 MB** | ⭐ Linux 镜像主力（运行时由镜像提供） |
| linux-x64 | 自包含 | 93.1 MB | 备选（镜像不带运行时） |
| win-x64 | 自包含 | 98.8 MB | 台式机（用户免装 .NET） |

**目标：≤ 250 MB** —— 当前全部达标。

> 对比：参考实现（WPF + CEF）是 **970 MB**。
> 我们的方案体积只有它的 **1/10**。

## 2. 发布命令

### Linux 镜像（主力）

```bash
dotnet publish client/src/YiHua.Pos.App/YiHua.Pos.App.csproj \
  -c Release -f net8.0 -r linux-x64 --self-contained false \
  -o publish/linux
```

**特点**：应用本体只有 22.7MB，.NET 运行时由镜像提供（镜像里装一次，多个应用共享）。

### Windows（台式机）

```powershell
dotnet publish client/src/YiHua.Pos.App/YiHua.Pos.App.csproj `
  -c Release -f net8.0 -r win-x64 --self-contained true `
  -o publish\win
```

**特点**：自带运行时，用户不需要装 .NET。

### Windows 7 保底

```powershell
dotnet publish client/src/YiHua.Pos.App/YiHua.Pos.App.csproj `
  -c Release -f net6.0 -r win-x64 --self-contained true `
  -o publish\win7
```

**说明**：net6.0 是支持 Windows 7 SP1 的最后一个版本。需随包分发 UCRT 兼容库。

## 3. ⚠️ 不能用的优化：PublishTrimmed

### 结论：**绝对不要开裁剪**

```xml
<!-- ❌ 会崩溃 -->
<PublishTrimmed>true</PublishTrimmed>
```

### 实测崩溃信息

```
Unhandled exception. DryIoc.ContainerException:
  code: Error.UnableToSelectSinglePublicConstructorFromNone;
  message: Unable to select a single public constructor from the implementation type
           'Prism.Ioc.Internals.ContainerProviderLocator'
           because the type does not have public constructors.
   at Prism.Container.DryIoc.DryIocContainerExtension..ctor(IContainer)
```

### 原因

.NET 裁剪器（ILLink）是**静态分析**的，它看不到 Prism/DryIoc 通过反射创建的类型。
`ContainerProviderLocator` 的构造函数被判定为"未被使用"而删除 → 运行时 DI 容器初始化失败。

### 影响面

Avalonia + Prism + DryIoc 这套组合**大量依赖反射**：
- DI 容器注册与解析
- XAML 绑定（非编译绑定部分）
- 视图-ViewModel 自动关联
- 区域导航

所以裁剪在这个技术栈上是**不安全**的。

### 实测对比

| 配置 | 体积 | 能否运行 |
|---|---|---|
| `PublishTrimmed=true` | 42.0 MB | ❌ 启动即崩 |
| `PublishTrimmed=false` | 98.8 MB | ✅ 正常 |
| `PublishTrimmed=false` + 框架依赖 | 22.7 MB | ✅ 正常 |

**用"框架依赖"来减体积，比用裁剪安全得多。**

## 4. 已启用的优化

写在 `client/Directory.Build.props`：

```xml
<PropertyGroup Condition="'$(Configuration)' == 'Release'">
  <PublishTrimmed>false</PublishTrimmed>
  <SatelliteResourceLanguages>zh-Hans;en</SatelliteResourceLanguages>
  <PublishReadyToRun>false</PublishReadyToRun>
</PropertyGroup>
```

| 配置 | 作用 |
|---|---|
| `PublishTrimmed=false` | 安全（见上） |
| `SatelliteResourceLanguages=zh-Hans;en` | 只打包中英文资源，不打包日韩俄等 |
| `PublishReadyToRun=false` | 体积优先；低配设备是机械硬盘，R2R 收益有限 |

## 5. 参考实现 vs 本方案（体积对比）

| 项 | 参考实现 | 本方案 |
|---|---|---|
| 框架 | WPF (.NET 6) | Avalonia (.NET 8) |
| 内嵌浏览器 | CEF（**188 MB**） | ❌ 不需要 |

| 数据库驱动 | **23 MB**（Oracle/DM/PG/MySQL 全打） | 只留 SQLite |
| **合计** | **970 MB** | **22.7 ~ 98.8 MB** |

## 6. CI 自动检查

`.github/workflows/build.yml` 每次推送自动执行：

```
① 客户端编译（net8.0 + net6.0 双目标）
② 客户端测试
③ 发布体积检查（linux-x64 框架依赖 + win-x64 自包含）
④ 服务端语法检查 + 冒烟测试
⑤ 越界检查（有没有改冻结文件）
⑥ 代码规范检查（硬编码路径 / 明文密钥 / 第三方代码痕迹）
```

体积超标会发 warning，越界修改会直接 fail。
