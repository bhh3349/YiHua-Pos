## 3. 验券（**核心交互：扫码**）

### 3.1 券是怎么来的（**别搞错**）

```
客人在美团/饿了么 App 里点开自己的券
  → App 显示一个二维码（券码就在二维码里）
  → 收银员用扫码枪扫这个二维码
  → 系统拿到券码 → 调服务端验券 → 显示券面信息
```

**平台代金券不是实体券，没有纸券。** 收银员不需要也不应该手输券码。

### 3.2 要求

- **扫码枪优先**：枪扫到二维码，回车即触发（收银员不做别的操作）
- 扫码枪在收银场景通常表现为「键盘输入 + 回车」，
  所以输入框要 **autofocus**、支持**扫码枪前缀后缀过滤**（防止把收银员敲的键也当券码）
- **手工输入只作为兜底**（客人二维码加载不出来时，让客人念券码）
- 验券只查不动钱，**验券失败不产生任何记录**
- 券面信息**大字显示**：面值、抵扣额、有效期、适用时段、使用门店
- 抵扣额不能超过应收 → 拒绝
- 券码**去空格 + 转大写**（二维码解码结果可能带空白）
- 平台名显示**中文**（美团/饿了么/抖音），不是 `meituan`

### 3.3 服务端接口（已定稿）

```
POST /api/v1/groupbuy/coupon/verify
     { platformCode, couponCode, storeId }

⚠️ 双层封装：data 字段里再套一层 JSON 字符串，必须反序列化两次
```

返回两个金额：
```
faceValue       面值（满 30 券，面值 30）
discountAmount  本单实际抵扣
```

**用 `discountAmount`**，界面同时显示面值。
平台按实际核销金额结账，用面值对不上账。

### 3.4 8 种券状态错误码，每种给人话

| 错误码 | 收银员看到的 |
|---|---|
| `COUPON_USED` | 这张券已经用过了，让客人出示新的券 |
| `COUPON_EXPIRED` | 券已过期，请客人确认有效期 |
| `COUPON_STORE_MISMATCH` | 这张券只能在指定门店使用 |
| `COUPON_TIME_RESTRICTED` | 这张券只能在特定时段用（如仅限午市） |
| `COUPON_NEED_BOOKING` | 这张券需要提前预约 |
| `COUPON_NOT_FOUND` | 券码不存在，请核对后重试 |
| `COUPON_NOT_YET_VALID` | 券还没到使用时间 |
| `PLATFORM_MISMATCH` | 这张券不属于该平台 |

理由：收银员看到「券无效」没法处理客人，
看到「只能在午市用」才知道该跟客人怎么说。

## 4. 核销

```
确认核销 → 幂等调用 → 成功 → 写回订单团购字段
```

**要求**：
- **核销幂等**：同一张券重复点核销不能重复扣
  （服务端已保证并发幂等，客户端要防重复点击）
- 核销按钮**点击后立即禁用**，直到有结果
- 成功后写回 `Order.GroupBuyPlatform` / `GroupBuyCouponCode` / `AmountGroupBuy`
- **核销失败不能改订单**

## 5. 断网怎么办（**用系统已有的优惠，不是新功能**）

断网验不了，但**抵扣额是确定的**（客人 App 上券面写着）。

```
收银员按券面金额直接打折 —— 就是优惠金额/抹零，本来就有
同时记下平台 + 券码，月底跟平台对账
```

**为什么不设计「手填团购抵扣额」**：

```
❌ 手填 → 这不是真实优惠，凭空多了一个收款方式
        → 报表显示「团购收入 30」，永远跟平台对不上
✅ 优惠金额 / 抹零 → 是真实优惠，优惠口径本来就装得下
```

**要求**：
- 提示说清该做什么：
  ```
  「券验证需要联网。可以按券面金额直接打折。」
  ```
  不是「网络错误，请稍后重试」
- **不要卡住收银**
- 券信息（平台 + 券码）**照样记**，月底对账用
- 走这条路的单有标记，能筛出来
- 抹零受 `CashRule.Rounding` 约束（抹到元 / 抹到角），超额度要提示

> 代金券功能在 T-603（会员模块），本卡**不重复造**，接口留好即可。

## 7. 逻辑要求（纯逻辑，重点测）

```csharp
public class CouponErrorMapper
{
    // 错误码 → 收银员看得懂的话
    string Map(string code, string serverMessage);
}

public class CouponInputNormalizer
{
    // 去空格、转大写
    string Normalize(string raw);
}

public class GroupBuyCalculator
{
    // 抵扣进优惠，不进实收
    (decimal AmountDiscount, decimal AmountPay) Apply(decimal orderTotal, decimal discount);

    // 抵扣不能超过应收
    bool ValidateDiscount(decimal discount, decimal payable, out string? error);

    // 用服务端 discountAmount，不用 faceValue
    decimal PickDiscount(CouponInfo coupon);
}
```

**必须覆盖的边界**：

| 场景 | 期望 |
|---|---|
| 二维码解码带空格/换行/小写 | 归一化后可验 |
| 扫码枪前缀后缀（部分扫码枪带 F9 触发 / 回车尾） | 正确过滤 |
| 券码为空 | 拒绝 + 提示 |
| 面值 ≠ 抵扣额 | **用 discountAmount** |
| 抵扣额 > 应收 | **拒绝** |
| 抵扣额 = 应收 | 允许，应收变 0 |
| 应收为 0 | 拒绝用券 |
| 券已过期 | 拒绝 + 过期话术 |
| 券不在有效期 | 拒绝 |
| 不同时段（午市券晚上用） | 拒绝 + 时段话术 |
| 非本店券 | 拒绝 |
| 已核销的券 | 拒绝 + 重核话术 |
| 重复点击核销 | **只成功一次** |
| 断网 | 提示按券面金额打折，**不要求新输入流程** |
| 抵扣 > 0 | **计入 AmountDiscount，不进实收** |
| 无效 JSON / 双层缺一层 | **不崩**，提示明确 |
| 9.995 取整 | 显式 `MidpointRounding.AwayFromZero` |

**禁止 float**，全程 decimal。
