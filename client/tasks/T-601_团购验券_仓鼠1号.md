## 2. 金额口径（**这是本卡最重要的一条，先看这个**）

团购券抵扣**算优惠，不算收款**。

```
订单原价 100
团购券抵扣 30        → 计入 AmountDiscount（优惠金额）
应收                70
实收（现金/微信）     70
```

所以：

```
Order.AmountTotal   = 100
Order.AmountDiscount = 30        ← 团购券抵扣进这里
Order.AmountPay      = 70
```

**整个营业额构成 = 实际收入 + 优惠金额**（报表口径，T-310 已实现）。

### 现有金额构成要加一项

现在（`OrderEntryViewModel` 第 537 行附近）是：

```csharp
AmountDiscount = totals.LineDiscountTotal + totals.OrderDiscount + totals.WipeZeroAmount
```

**要变成四项**：

```csharp
AmountDiscount = totals.LineDiscountTotal
               + totals.OrderDiscount
               + totals.GroupBuyDiscount      // ← 新增
               + totals.WipeZeroAmount
```

> ⚠️ 这一行在 `ViewModels/Ordering/`，**属于别人的目录，本卡不改**。
> 你在本卡实现时，**用以下任一方式**（报告里说明选了哪种）：
> ① 把计算逻辑放进 `Services/GroupBuy/`，只对外暴露一个函数，
>    由 Ordering 那边接一行（需要我在合并时补那一行）
> ② 或者本卡只交付团购部分，Ordering 那一行由我统一改

### ⚠️ 绝对不要把团购记成一笔收款

```
❌ 记成收款：团购 70 元   → 报表显示「团购收入 70」，跟平台账单对不上
✅ 记成优惠：优惠 30，实收 70 → 报表显示「团购抵扣 30」，对得上
```

**平台给你结的是核销金额（抵扣额），不是客人实付额。**

端点前缀 `/api/v1/groupbuy`，全部 POST：

```
/platformList    平台列表
/configList      平台配置
/coupon/verify   验券（不出账）
/coupon/redeem   核销（真扣）
```

请求体（`verify` 与 `redeem` 共用字段）：

```json
{
  "platformCode": "self",
  "couponCode": "ABC123",
  "storeId": 0,
  "orderId": 0
}
```

`storeId` 传 0 表示用当前门店。`orderId` 传 0 表示未关联订单。

**双层封装**：业务响应是 `data` 字段里再套一层 JSON 字符串，**必须反序列化两次**。

## 3. 8 种券状态错误码（**不要笼统提示「券无效」**）

```
COUPON_NOT_FOUND         券码不存在
COUPON_USED              已核销
COUPON_NOT_YET_VALID     未到有效期
COUPON_EXPIRED           已过期
COUPON_STORE_MISMATCH    不适用于本店
COUPON_TIME_RESTRICTED   当前时段不可用
COUPON_NEED_BOOKING      需要预约
PLATFORM_MISMATCH        不属于该平台
```

**每种要给收银员不同的处理建议**，不能只显示服务端原文：

| 错误码 | 收银员看到的 |
|---|---|
| `COUPON_USED` | 这张券已经用过了，让客人出示新的券 |
| `COUPON_EXPIRED` | 券已过期，请客人确认有效期 |
| `COUPON_STORE_MISMATCH` | 这张券只能在指定门店使用 |
| `COUPON_TIME_RESTRICTED` | 这张券只能在特定时段用（如仅限午市） |
| `COUPON_NEED_BOOKING` | 这张券需要提前预约 |
| `COUPON_NOT_FOUND` | 券码不存在，请核对后重试 |

**理由**：收银员看到「券无效」没法处理客人，看到「只能在午市用」才知道该说什么。

## 4. 功能要求

### 4.1 验券（**核心交互**）

```
输入券码 → 校验 → 显示券面信息 → 确认后核销
```

**要求**：
- **扫码枪优先**：支持枪输入，回车即触发（收银员不做手工输入）
- **手工输入兜底**：枪坏了还能手输
- 验券只查不动钱，**验券失败不产生任何记录**
- 验券成功后要**大字显示**：券面值、抵扣额、有效期、适用时段、使用门店
- **券信息必须和当前订单能对上**：抵扣额不能超过订单应付，否则拒绝
- 券码要**去空格 + 转大写**（客人从微信复制出来常带空格）
- 网络不通时**明确提示「验券需要联网」**，不要说「网络错误」

### 4.2 核销

```
确认核销 → 幂等调用 → 成功 → 写回订单团购字段
```

**要求**：
- **核销必须幂等**：同一张券重复点核销，不能重复扣
  （服务端已保证并发幂等，客户端要防重复点击）
- 核销按钮**点击后立即禁用**，直到有结果
- 成功后写回 `Order.GroupBuyPlatform` / `GroupBuyCouponCode` / `AmountGroupBuy`
- **核销失败不能改订单**（宁可让客人重新来一次，也不能账不一致）

### 4.3 核销记录

```
按订单 / 按券码 / 按平台 查询核销流水
```

**要求**：
- 能看到：什么时候核的、哪个平台、抵了多少、谁操作的
- 能看到**撤销记录**（`coupon/reverse`）
- 要能**重复打印核销小票**

### 4.4 断网兜底：手动记团购（**验券保留，这是备用路径**）

**正常情况走验券流程，不要砍。** 断网时验不了，这时才用手动记账。

```
断网 → 收银员手动录一笔团购抵扣 → 照样记账 → 联网后不影响
```

**要求**：
- 手动入口要在**容易找到的地方**，不要藏在设置里（收银员不会找）
  - 建议放在**收款区**，作为「团购」这一项
- 录入内容尽量少，**三样就够**：

```
平台    美团 / 饿了么 / 抖音 / 自有 / 其他   ← 选择列表，默认「自有」
抵扣金额  30                                ← 必填
券码     （选填）                           ← 有就填，方便对账
```

- **抵扣金额不能超过订单应收**，否则算成负数 → 拒绝
- 手动记的这单要**标记来源**（手动 vs 验券），月底能查
- **不要弹「联网失败请稍后重试」就卡住收银** ——
  说一句「券验证需要联网，可以手动记录团购抵扣」，两个按钮，收银员自己选

> ⚠️ 手动记账**不等于**跳过平台核销。平台那边的核销是平台的事，
> 收银系统只管记账，对账时手动记的这几单单独列出来就行。

### 4.5 券抵扣额以谁为准（**已确认口径**）

服务端返回两个值：

```
faceValue       面值（满 100 的券，面值 100）
discountAmount  本单实际抵扣（本单只用了 35）
```

**用 `discountAmount`**，界面同时显示面值让收银员知道。

理由：平台结账按实际核销金额算，用面值对不上账。

```
查看已接入平台 / 哪些平台启用了
```

**要求**：
- 未接入的平台要**明确显示「未接入」**，不能点一下才报错
- 平台配置（密钥、绑定门店）**不在客户端改**，只读展示

### 4.6 平台管理（只读）

```
查看已接入平台 / 哪些平台启用了
```

**要求**：
- 未接入的平台要**明确显示「未接入」并置灰**，不要让老板点了才知道
- 平台配置（密钥、绑定门店）**不在客户端改**，只读展示
- 平台名显示**中文**（美团/饿了么/抖音），不是 `meituan`

## 5. 逻辑要求（纯逻辑，重点测）

```csharp
public class CouponErrorMapper
{
    // 错误码 → 收银员看得懂的话
    string Map(string code, string serverMessage);
}

public class CouponInputNormalizer
{
    // 去空格、转大写（微信复制常带空格和换行）
    string Normalize(string raw);
}

public class CouponValidator
{
    // 券状态是否可用于当前订单
    bool CanApply(CouponInfo coupon, decimal orderPayable, out string? error);

    // 抵扣额不能超过应收
    bool ValidateDiscount(decimal discount, decimal payable, out string? error);

    // 有效期 / 时段 / 门店
    bool ValidateWindow(CouponInfo c, DateTime now, out string? error);
}

public class ManualGroupBuyCalculator
{
    // 手动记团购（断网兜底）：抵扣额不能超过应收
    bool ValidateManual(decimal discount, decimal orderPayable, out string? error);

    // 抵扣进优惠，不进实收
    (decimal AmountDiscount, decimal AmountPay) Apply(decimal orderTotal, decimal discount);
}
```

**必须覆盖的边界**：

| 场景 | 期望 |
|---|---|
| 券码带空格/换行/小写 | 归一化后可验 |
| 券码为空 | 拒绝 + 提示 |
| 抵扣额 > 订单应付 | 拒绝 |
| 抵扣额 = 订单应付（刚好抵完） | 允许，订单应付变 0 |
| 订单应付为 0 | 拒绝用券 |
| 券已过期 | 拒绝 + 过期话术 |
| 券不在有效期 | 拒绝 |
| 不同时段（午市券晚上用） | 拒绝 + 时段话术 |
| 非本店券 | 拒绝 |
| 已核销的券 | 拒绝 + 重核话术 |
| 重复点击核销 | **只成功一次** |
| 券面值 > 本单抵扣 | 用 discountAmount，不用 faceValue |
| **手动记团购：抵扣 > 应收** | **拒绝** |
| **手动记团购：抵扣 = 应收** | 允许，实收变 0 |
| **手动记团购：不填抵扣金额** | **拒绝** |
| 手动记团购不填平台 | 默认「自有」 |
| 团购抵扣额 > 0 | **计入 AmountDiscount（优惠），不进实收** |
| 验券失败 | 提示 + 提供手动记录入口，不卡住收银 |
| 网络不通 | 明确提示「验券需要联网」，不崩 |

**取整**：显式 `MidpointRounding.AwayFromZero`，全程 decimal。
