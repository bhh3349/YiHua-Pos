## 2. 业务背景

**正餐（火锅/中餐）场景**：客人坐下点菜，服务员在**桌台**上开台、点单、结账。

桌台管理要解决：
```
- 现在哪些桌子空着、哪些有人
- 新客来了要开台
- 客人要换桌（拼桌/挪桌）
- 客人走了要清台
- 预定桌要留位
```

**快餐场景不用桌台** —— 所以桌台页要支持一键隐藏。

## 3. 功能要求

### 3.1 桌台视图（主界面）

```
┌──────────────────────────────────────────────┐
│  区域筛选：[全部][大厅][包间][二楼]   [+ 开台] │
├──────────────────────────────────────────────┤
│  ┌────────┐ ┌────────┐ ┌────────┐            │
│  │  A01   │ │  A02   │ │  A03   │  ← DeskCard│
│  │ 4人·25分│ │ ●占用  │ │ ●预订  │            │
│  │ ¥128.00│ │ ¥86.00 │ │ 18:00  │            │
│  └────────┘ └────────┘ └────────┘            │
└──────────────────────────────────────────────┘
```

**用 `UI/Controls/Cards/DeskCard.cs`（已完成）**，它的状态色是：
- 空闲 `DeskIdleBrush`
- 占用 `DeskOccupiedBrush`
- 预订 `DeskReservedBrush`

**要求**：
- 按区域筛选（区域数据从 `Desk.Area` 来）
- 状态筛选（全部/空闲/占用/预订）
- 卡片点击 → 打开该桌操作菜单
- 定时刷新占用时长（每 30 秒）
- **空闲桌放前面还是占用桌放前面？** —— 收银员找空桌最快，放空闲在前；但要提供排序切换

### 3.2 开台

```
选桌（点空闲卡）→ 填就餐人数 → 确认
```

- 人数用 `NumberPad`（已有）输入
- 可选：预订单关联（选了预订桌时自动带出）
- 开台后进入该桌的点单界面（**只发事件，不直接调用点单模块**）

### 3.3 换台（挪台）

```
源桌 → 选目标空桌 → 确认
```

- 目标桌必须是**空闲**
- **明细要全部搬到目标桌**，不是新建
- 目标桌继承源桌的就餐人数
- 源桌变空闲
- 要有二次确认（防止误操作把正在结账的桌挪走）

**边界情况**：
- 源桌有已结账未清的明细 → 拒绝，提示先清台
- 目标桌被其他人抢占了 → 报错，刷新界面

### 3.4 并台

```
源桌 + 目标桌 → 合并
```

- 两桌都是**占用**状态
- 明细合并到其中一桌
- 另一桌变空闲
- 人数相加
- 二次确认

### 3.5 清台

```
占用桌 → 确认 → 空闲
```

- **必须已结账**，未结账要阻止并提示
- 清台后写入开台记录（谁清的、几点）

### 3.6 预订

```
建预订 → 桌号 + 时间 + 人数 + 客人名 + 电话（可选）
```

- 到点未到的预订，桌台视图给个提示（快到了/已过 15 分钟）
- 客人到了 → 一键开台（带出人数）

## 4. 状态机

桌台状态流转要明确，**用枚举 + 明确的转换方法**，不要到处 `if`：

```
空闲 ──开台──> 占用 ──结账+清台──> 空闲
  │                │
  └──预订──> 预订 ──到店开台──> 占用
  │                │
  └──取消预订──> 空闲                └──撤销(未结账)──> 空闲
```

**必须测试的非法转换**：
- 空闲桌换台 → 拒绝
- 空闲桌并台 → 拒绝
- 未结账桌清台 → 拒绝
- 预订桌直接清台 → 拒绝
- 占用桌重复开台 → 拒绝

## 5. UI 工艺要求（硬性）

必读 `client/tasks/T-005_控件库_仓鼠3号.md` 第 3 节。

**Craft Read 参考**：
- `CRAFT_LEVEL` 8 / `MOTION_INTENSITY` 2 / `VISUAL_DENSITY` 8 / `DESIGN_VARIANCE` 3
- 桌台页信息密度要高（收银员要一眼看到全局），但**不能靠缩小字号**，靠布局和分组
- 签名动作建议：**桌台卡片上直接显示开台时长和人数变化趋势**，让收银员判断桌型

**状态覆盖**（每个操作面）：
```
idle / loading / empty / error / success / conflict
```
**empty 是阻塞级**——「今天还没有开台」要设计成邀请行动的入口，不是干巴巴一句空话。

**注意**：
- 桌号字号要大（收银员远距离扫一眼）
- 金额用 `AmountDisplay`（已有，tabular-nums）
- 不要用彩色边框表达状态，底色区分（DeskCard 已经这么做了）
- 换台/并台/清台是破坏性操作 → 用 `ConfirmDialog`（已有）
