## 2. 交班是账务的分界线

```
早班收银员张三 09:00 开班
  ├─ 收了 50 笔现金
  ├─ 找了 20 笔零钱
  └─ 16:30 交班给李四

李四要核对：
  系统算：本班应收 8,600，实收现金 8,520
  钱箱实际：8,450
  差额：-70  ← 短款
```

**核心原则：交班时钱必须对得上，对不上要说清楚。**

**常见班次**：
```
早班 09:00-16:00   午市+下午茶
晚班 16:00-次日02:00  晚餐+夜宵
全天班 09:00-次日02:00
自定义
```

## 3. 功能要求

### 3.1 开班

```
登录后如果没有未关闭的班 → 提示开班
开班要交「备用金」（钱箱初始现金）
```

- 备用金：老板给收银员启动钱箱的钱（如 500）
- 要能预设每班备用金额，也能每次手输
- 已有未关闭班 → **拒绝开新班**（防重复）

### 3.2 班中（持续统计）

班进行中要实时看到：
```
本班订单     128 笔
本班应收     ¥8,600.00
  现金       ¥5,200.00
  记账       ¥1,800.00
  自定义收款 ¥1,600.00
本班优惠     ¥320.00
本班退菜     3 笔 / ¥88.00
本班冲正     1 笔 / ¥56.00
钱箱应有     ¥5,700.00  （备用金500 + 现金收入5200）
```

### 3.3 交班（核心）

```
点「交班」→ 对账 → 确认
```

**对账页面要显示**：

```
【系统数据】                【清点数据】
现金应收      ¥5,200.00     钱箱实点    ¥5,450.00
记账          ¥1,800.00     备用金      ¥   500.00
自定义收款    ¥1,600.00
─────────────────────      ─────────────────────
合计          ¥8,600.00     合计        ¥5,950.00

【差额】
现金差额 = 钱箱实点 - 现金应收
         = 5,450 - 5,200 = +250（溢余）

【操作】
差额原因：[选择或填写]
处理方式：[暂存差异 / 要求重算]
```

**要求**：
- **差额必须显示具体数字和正负号**，不能只说「不平」
- 差异原因要选：数错了/ 找错零了/ 收了私单/ 抹零没记/ 现金被盗/ 其他
- **原因必填**（不能空着交班）
- 交班后打印**交班单**（`TemplateType.Handover` 已有）
- 交班后钱箱记录存档，**下一班的备用金 = 实际剩余**（老板决定留多少）

### 3.4 交班历史

```
能查历史班次：
  日期 / 班次 / 收银员 / 订单数 / 应收 / 实收 / 差额 / 原因
```

- 能看某一班的明细（哪些订单）
- 能重打交班单
- **不允许修改已关闭的班**（财务凭证）

### 3.5 强制交班

**关键运营需求**：
```
晚班 02:00 结束，但李四忘了交班，
第二天张三来了，发现还有个未关闭的班 → 不能开新班！
```

**要求**：
- 未交班时，下一个收银员登录要**醒目提示**「上一班未交班」
- 提供「强制交班」按钮（**仅店长**）
- 强制交班会记录操作人，并标注「强制」

## 4. 计算逻辑（**必须精确**）

单独抽纯逻辑类，重点测：

```csharp
public class ShiftCalculator
{
    // 本班各支付方式应收
    decimal SumByPayType(long shiftId, PayType type);
    
    // 钱箱应有 = 备用金 + 现金收入 - 现金退款
    decimal ExpectedCashInDrawer(decimal openingFloat, decimal cashIncome, decimal cashRefund);
    
    // 差额 = 实点 - 应有
    decimal CalculateDifference(decimal actualCash, decimal expectedCash);
    
    // 退菜和冲正要冲减还是保留？—— 明确规则
    decimal NetAmount(long shiftId);
}
```

**必须明确的规则**（在报告里写清楚）：

| 问题 | 规则 |
|---|---|
| 退菜退的是现金 | 现金应收减少 |
| 冲正单金额是负数 | 直接计入还是排除？ |
| 抹零 | 抹掉的部分算优惠还是不算？ |
| 记账收回（后续还款） | 算在本班还是回原班？ |
| 备用金不足时 | 差额算短款 |

**取整**：显式 `MidpointRounding.AwayFromZero`。

## 5. ⚠️ Domain 缺口（**不要自己改**）

`Order` 有 `ShiftId`、`AmountReceived`、`AmountChange`，`ShiftStatus` 枚举已有。

**缺的**：

| 缺口 | 用途 |
|---|---|
| `Shift` 实体 | 班次：开班时间/收银员/备用金/关闭时间/实点金额/差额/原因 |
| `IShiftRepository` | 班次仓储 |
| `ShiftDifference` 实体 | 交班时的差异记录（金额、原因、处理人） |
| `OpeningFloat` | 备用金字段（`Order` 上没有） |

**处理方式**：**不要改 Domain**（冻结），在报告里列「Domain 缺口清单」。

**同时**：把计算逻辑做成纯类（`ShiftCalculator`），先用假数据测；仓储用**可注入接口 + 假实现**。

## 6. UI 工艺要求

必读 `client/tasks/T-005_控件库_仓鼠3号.md` 第 3 节。

**Craft Read 参考**：
- `CRAFT_LEVEL` 8 / `MOTION_INTENSITY` 2 / `VISUAL_DENSITY` 7 / `DESIGN_VARIANCE` 3

**关键要求**：
- **差额数字要最醒目**（这是收银员最紧张的数字）
  - 短款（负）用警告色，溢余（正）用中性色，不要一律红色
  - 显示正负号和绝对值，不要只显示 `¥-70`
- 对账页面**左右分栏**（系统数据 vs 实点数据），方便逐行核对
- 原因选择用**下拉/分段**，不要让收银员打字（但要留「其他」手输）
- 交班确认弹窗要显示**具体影响**（不是「确定吗」）
- 历史列表金额右对齐 tabular-nums（用 `AmountDisplay`）
- 强制交班要有**权限门控 + 二次确认 + 记录操作人**
- 未交班提示要**阻塞级**（不能一点就过了）
- empty / loading / error 四态
- 短款超过阈值（如 ¥100）建议**必须店长确认**（做成可配置）
