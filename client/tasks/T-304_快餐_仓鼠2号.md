## 2. 两种餐饮形态

```
正餐（DineIn）        快餐（FastFood）
─────────────         ─────────────
有桌台                没桌台
服务员巡台点单        客人自己点
按桌结账              排队取号，取号结账
桌台 A08              取号 A052
```

**一个店可以两种都有**（比如同时做堂食和外卖）。所以**不是两套程序，是一个程序两种模式**，由 `StoreMode` 决定（枚举已有）。

## 3. 功能要求

### 3.1 取号

```
客人到店 → 排队 → 叫号 → 点单 → 结账 → 走人
```

**取号页要做**：
- 显示当前排队人数
- 发号（按日序号，如 A052）
- 叫号（跳下一个，也可以指定某个号）
- **改号/退号**（客人走了）
- **插队**（老客人来了，给个前面的号）

**叫号屏要显示**：
```
当前：A051  ← 已叫，正在点单
前面：A052 A053
等待：4人
```

### 3.2 快餐点单

复用 T-303 的点单界面，差异：

| 项 | 正餐 | 快餐 |
|---|---|---|
| 明细有桌号 | A08 | 取号 A052 |
| 结账时机 | 客人走了结账 | 点完立刻结账 |
| 挂单 | 需要 | 一般不用 |
| 退菜 | 常见 | 少见（未结账时可直接删） |

**关键差异：快餐是「先付后吃」**
```
点完 → 必须结账 → 才能叫下一号
未结账的单不能放走（要提示）
```

**要求**：
- 快餐模式下**不显示桌台选择**，改显示取号
- 明细区标题显示「取号 A052 · 3 位」
- 结账按钮文案从「结账」改成「点单完成」更直观

### 3.3 就餐方式

快餐常见三种（`OrderType` 枚举已有）：
```
堂食（DineIn）      坐下吃，用餐具
外带（TakeAway）    打包带走
配送（Delivery）    外卖，客人留地址电话
```

**要求**：
- 结账页让选择就餐方式
- 外带/配送要能留备注（餐具数量：几双筷子、几份餐具）
- 配送要留地址电话（**这个是团购平台对接要用的**，见 T-405）

### 3.4 叫号大屏

**这是快餐店最需要的功能**，客人坐着等，不能一直盯着服务员。

```
┌──────────────────────────────────────┐
│                                      │
│           A052                       │  ← 超大字号
│        正在点单                       │
│                                      │
│  等待：A053 A054 A055                │
│                                      │
└──────────────────────────────────────┘
```

**技术要求**：
- 走**副屏**（`Hardware/Devices/SecondaryScreenManager`，T-106 已实现）
- **副屏没接也要能跑**（降级到主窗口全屏）
- 可切换：显示取号 / 显示取号+当前单金额
- 字号要能在 3 米外看清

## 5. ⚠️ Domain 缺口（**不要自己改**）

`Order` 实体已有 `TakeNo`、`OrderType`、`GuestCount`，**快餐核心字段都在**。

但**缺这些**：

| 缺口 | 用途 |
|---|---|
| `TakeNoSequence`（发号器） | 今日发号计数与重置 |
| 取号记录实体 | 叫号队列：号、状态（等待/叫号中/已完成）、时间 |
| `DeliveryAddress` / `DeliveryPhone` | 配送信息 |
| `TablewareCount` | 餐具数量（外带常用） |

**处理方式**：**不要改 Domain**（冻结）。
在报告里列「Domain 缺口清单」，我统一加。

**同时**：把取号队列、发号器做成**纯内存 + 可注入接口**（`ITicketQueue`），先用假实现跑通逻辑。

## 6. UI 工艺要求

必读 `client/tasks/T-005_控件库_仓鼠3号.md` 第 3 节。

**Craft Read 参考**：
- `CRAFT_LEVEL` 8 / `MOTION_INTENSITY` 3 / `VISUAL_DENSITY` 8 / `DESIGN_VARIANCE` 3
- 叫号屏 `CRAFT_LEVEL` 6 / `MOTION_INTENSITY` 2 / `VISUAL_DENSITY` 1（极简，一个信息）
- 动效强度比正餐高一点（叫号是动态的），但**只用 opacity/translate，不要 scale/bounce**

**关键要求**：
- **叫号屏字号必须够大**（3 米外能看清）——不要为了「好看」缩小
- 叫号屏要有**高对比度**（灯光亮的环境）
- 「点单完成」按钮要**明显区别于**正餐的「结账」——快餐是高频动作
- 快餐模式下**隐藏桌台相关的一切**（不显示桌台选择、不显示开台按钮）
- empty / loading / error / conflict 四态
- 取号队列为空要有设计（不是「暂无数据」）
- 副屏不可用时要**明确降级提示**，不能静默失败
