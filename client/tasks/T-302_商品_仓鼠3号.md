## 2. 业务背景

**餐饮商品结构和商超完全不同**，这是这个模块最容易做错的地方。

### 2.1 关键差异

| 商超 POS | **餐饮 POS** |
|---|---|
| 一个商品一个价格 | **一个商品多个规格**（小份/大份/中份） |
| 就是个名字 | 商品有**别名**（客人说「牛肉面」，系统叫「兰州牛肉面(小)」） |
| 没有单位概念 | **必须有单位**：份/例/杯/两/斤/串 |
| 数字随便填 | **必须可称重**（海鲜按斤，价格随重量变） |
| 套餐少见 | **套餐/组合**很常见（双人套餐A） |
| 卖完就下架 | **沽清**是日常（今天牛肉面卖完了） |
| 固定价格 | **时价**（今天的鱼38，明天可能42） |

### 2.2 正餐 vs 快餐的商品结构差异

```
正餐（中餐/火锅）：
  菜名 + 规格（小份/大份）+ 单位（例/份）+ 做法备注
  
快餐（茶饮/小吃）：
  商品名 + 规格（大杯/中杯/小杯）+ 多级选项
    温度：热/去冰/少冰/多冰
    糖度：全糖/七分/五分/三分/无糖
    加料：珍珠/椰果/布丁（+2元）
    → 这叫「规格组」，一个维度多选项
```

**这是本任务的重点**：规格组要能表达茶饮那种多维度配置。

## 3. 功能要求

### 3.1 商品列表

```
┌───────────────────────────────────────────────┐
│ 分类：[热销][主食][小吃][饮品]   [+ 新建商品]   │
│ 搜索：[____________]  筛选：[在售][沽清][全部] │
├───────────────────────────────────────────────┤
│ ┌─────────┐ ┌─────────┐ ┌─────────┐           │
│ │ 牛肉面  │ │ 宫保鸡丁│ │ 珍珠奶茶│  ← ProductCard│
│ │ 小/中/大│ │ ¥38.00  │ │ ¥12.00  │           │
│ │ 例  ✓在售│ │ 例  称重│ │ 杯  沽清│           │
│ └─────────┘ └─────────┘ └─────────┘           │
└───────────────────────────────────────────────┘
```

**要求**：
- 按分类筛选 + 关键词搜索
- 状态筛选（在售 / 沽清 / 全部）
- 列表项显示：`ProductCard` 已有（名称/价格/单位/称重标记/售罄标记）
- 点卡片 → 编辑
- 长按 → 快捷菜单（沽清/复制/删除）

### 3.2 商品编辑（核心）

```
基础信息
├─ 商品名称（必填）
├─ 别名（多个，逗号分隔，用于快速搜索）
├─ 分类（必选）
├─ 单位（份/例/杯/两/斤/串/…）
├─ 是否称重
├─ 是否套餐
└─ 图片

规格设置
├─ 无规格：单一价格
└─ 有规格：
   ├─ 规格维度（如「大小」「温度」「糖度」）
   ├─ 每个维度的选项（如 大杯/中杯/小杯）
   ├─ 维度之间是否可组合（茶饮：可；火锅锅底：通常不可）
   └─ 组合价格（默认继承基础价，可覆盖）

时价
└─ 勾选后每日需确认当日价格
```

**要求**：
- 别名搜索：输入「牛肉」能搜到「兰州牛肉面(小)」
- 规格组合数有上限提示（茶饮 3 维 × 4 选项 = 64 种，要警告）
- 必填校验要给明确提示，不是静默拒绝
- 删除商品要提示「有历史订单的商品建议停用而非删除」

### 3.3 沽清

**这是日常高频操作**，必须做得快：

```
方式一：列表长按 → 沽清
方式二：沽清页批量操作（显示今天沽清的所有商品）
```

- 沽清是可逆的（恢复在售）
- 沽清状态要能同步到其他收银机（服务端负责）
- **离线时沽清也要生效**（数据层 outbox 会处理）

### 3.4 套餐

```
套餐 = 主菜 + 若干配料 + 固定售价
├─ 从已有商品里选
├─ 支持「固定搭配」（A套餐 = 牛肉面 + 小菜 + 饮料）
└─ 售价可与单品总价不同
```

**要求**：
- 套餐里的商品**从库**（数量不能改、沽清跟着主商品联动）
- 但**售价按套餐算**（不是单品价格相加）
- 套餐打印小票要能展开明细

### 3.5 分类管理

```
新建/重命名/排序/隐藏（隐藏后前台不显示但保留历史数据）
```

- 分类删除前必须检查是否有关联商品
- 分类拖拽排序（触控要能拖）

## 4. UI 工艺要求（硬性）

必读 `client/tasks/T-005_控件库_仓鼠3号.md` 第 3 节。

**Craft Read 参考**（你上一个任务 T-005 的延续，要保持视觉一致）：
- `CRAFT_LEVEL` 8 / `MOTION_INTENSITY` 2 / `VISUAL_DENSITY` 7 / `DESIGN_VARIANCE` 3
- 商品管理是「后台」界面，收银员天天用，效率优先

**关键要求**：
- **商品编辑页是表单**，长表单必须有**分组 + 分段导航**，不能让收银员滚一屏找字段
- **保存按钮固定**（滚动时也在），不要让用户滚到底才找得到
- 数字输入一律用 `NumberPad`（已有），不要用系统键盘
- 规格编辑器要能**预览实际下单时显示的样子**
- 沽清开关要**一眼看出状态**，不能靠记颜色
- empty / loading / error 三态必做（阻塞级）
- destructive 操作（删除商品/分类）必须二次确认
