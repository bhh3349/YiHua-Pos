## 0. 为什么这个要做

你现在准备**299 买断卖给小商家**。那么：

```
商家第一次装上你的软件，必须自己配置好这些才能用：
  □ 打印机连哪台、58mm 还是 80mm、几联
  □ 本店有几个档口、每个档口打哪张单
  □ 小票抬头、店名、地址、电话
  □ 服务员账号、每个人权限
  □ 抹零规则、折扣规则
  □ 系统是联网还是单机
```

**这些现在都没有统一入口。** 小商家不懂技术，装完不会配 = 老板直接骂娘。

**这是 299 定价能不能成立的前提**。

## 2. 功能要求

### 2.1 门店信息

```
店名、地址、电话、logo
```

**要求**：
- 店名要能**自动带到小票上**（复用 T-107 的模板）
- logo 要能上传（**小票上显示店名logo 是提升专业感的最低成本手段**）
- logo 要**自动压缩**（小票打印是位图，太大会卡）
- 必填项要**明确标出**（不是红星，要告诉用户为什么必填）

### 2.2 打印机管理（**最重要**）

```
配置：打印机名称 / 类型（58mm、80mm）/ 用途（小票、后厨、标签、交班单）/ 打印档口
```

**要求**：
- **必须能测试打印**：配完打印机，**立刻能打一张测试页**确认能用
  ← 这条是小商家最需要的，没有测试打印他们不知道怎么调
- 要显示打印机**当前状态**（在线/离线/缺纸）
- 要能**自动发现**本机打印机（列出可用的）
- **一张单可以设多台打印机**（前厅小票 + 后厨单分打）
- 要能指定**每个档口打给哪台后厨打印机**
- 打印失败要有**明确提示 + 重试**

**关键约束**：
```
Linux 版：/dev/usb/lp*、/dev/ttyUSB*、/dev/ttyACM*、/dev/rfcomm*、TCP 9100
Windows 版：共享打印机、COM口、USB
两个平台的设备路径完全不同，要分平台处理
```

### 2.3 收银规则

```
抹零规则（不抹零/抹到角/抹到元）
折扣规则（单品折扣、整单折扣、会员折扣）
小票打印内容（是否显示明细、是否显示折扣、是否显示二维码）
```

**要求**：
- 抹零规则要**预览示例**（输入 ¥38.5，按当前规则显示「抹到元→ ¥38.0」）
- 小票打印内容要**有预览**（选什么就看到什么效果）
  ← 这复用T-107 的 `RenderPreview`，不要重造
- 规则要有**默认配置**，不要让商家从零配

### 2.4 账号与权限

```
服务员列表、角色分配、密码重置
```

**要求**：
- 复用 T-301 已有的登录/权限体系（**不要重造**）
- 要能**禁用账号**（员工离职），但**保留历史订单的操作人**
  ← 这条很重要，财务凭证不能因为员工离职就查不到
- 密码重置要有**权限控制**（普通服务员不能重置别人密码）

### 2.5 系统信息与备份（**售后命脉**）

```
版本号、运行环境、数据库路径、磁盘空间
一键备份、一键恢复、导出诊断报告
```

**要求**：
- **版本号要显眼**（客服第一句话就是「你什么版本」）
- **一键备份**：导出整个数据库文件
- **一键恢复**：从备份文件恢复（**恢复前必须二次确认 + 自动备份当前数据**）
- **诊断报告**（这个直接决定你的售后成本）：
  - 系统版本、.NET/Avalonia 版本、操作系统
  - 打印机列表与状态
  - 网络状态、服务器连接状态
  - 数据库文件大小、完整性、表记录数
  - **最近 7 天的错误日志**
  - 生成成一个文件，商家截图发你，你 30 秒看懂

**⚠️ 诊断报告是这一卡最重要的功能**：
```
没有它：商家描述问题 → 你远程连过去 → 每次 30 分钟
  有它：商家点一下 → 发文件给你 → 你 30 秒看完
```

### 2.6 关于联网/单机

```
当前是单机模式还是联网模式？
服务器地址是什么？
同步状态如何？
```

**要求**：
- 要显示**当前同步状态**（已同步/待同步 N 笔/同步失败）
- 要能**手动触发同步**
- 要显示**上次同步时间**
- 服务器地址要**可配置**（现在填默认，以后域名上线改这里就行）

## 4. 逻辑要求（**必须精确**）

```csharp
public class SettingsValidator
{
    // 店名必填（要打到小票上）
    bool ValidateStoreName(string name, out string? error);
    
    // 打印机配置校验：至少要有1 台能打小票的
    bool ValidatePrinters(IReadOnlyList<PrinterConfig> printers, out string? error);
    
    // 抹零计算预览
    decimal ApplyRounding(decimal amount, RoundingRule rule);
    
    // logo 大小/格式校验
    bool ValidateLogo(byte[] data, out string? error);
}

public class DiagnosticReportBuilder
{
    // 汇总系统信息 + 打印机状态 + 数据库状态 + 错误日志
    string Build();
}
```

**必须覆盖的边界**：

| 场景 | 期望 |
|---|---|
| 店名为空 | 拒绝 |
| 没有可用打印机 | 明确提示 |
| logo 超过大小限制 | 拒绝 + 说明限制 |
| logo 格式不支持 | 拒绝 |
| 抹零规则切换 | 预览实时更新 |
| 备份文件损坏 | 恢复失败要明确提示，不能崩 |
| 恢复前未备份当前数据 | 必须二次确认 |
| 数据库不存在 | 诊断报告不能崩，要显示"未创建" |
| 网络断开 | 同步状态显示离线，不能卡住 |

**取整**：显式 `MidpointRounding.AwayFromZero`。

## 5. ⚠️ Domain 缺口（**不要自己改**）

**缺的**：

| 缺口 | 用途 |
|---|---|
| `StoreSetting` 实体 | 门店信息配置 |
| `IStoreSettingRepository` | 配置仓储 |
| `PrinterConfig` 实体 | 打印机配置（名称/类型/用途/档口） |
| `IPrinterConfigRepository` | 打印机配置仓储 |
| `SystemConfig` 实体 | 系统级配置（服务器地址/同步开关） |

**处理方式**：**不要改 Domain**（冻结），在报告里列「Domain 缺口清单」。

**同时**：
- 配置读写做成**接口 + 假实现**（`ISettingsStore`），你负责 UI 和校验逻辑
- 诊断报告用**纯文本/Markdown**输出，不依赖任何存储

## 6. UI 工艺要求

必读 `client/tasks/T-005_控件库_仓鼠3号.md` 第 3 节。

**Craft Read**：`CRAFT_LEVEL` 6 / `MOTION_INTENSITY` 2 / `VISUAL_DENSITY` 6 / `DESIGN_VARIANCE` 2`

**关键要求**：

- **设置界面要"安静"**：用户来这里是来改配置的，不是来欣赏设计的
  - 少动效、少装饰、高信息密度
  - 不要转场动画
- **「测试打印」按钮要最显眼**——这是打印机配置页的核心动作
- **状态用颜色 + 文字双重要**（不要只靠颜色，色盲用户看不到）
  - 在线用绿色圆点 + "在线"
  - 离线用灰色 + "未连接"
- **必填项要有文字说明**，不是只打红星
- **危险操作要二次确认**：恢复数据、批量清理
  - 确认弹窗要说明**具体后果**
- **logo 上传要有预览**，让用户知道传成什么样
- 预览区（抹零、小票）要**实时更新**
- **错误信息要说人话**：「打印机连接失败，检查线缆或换一个 USB 口」，不是「PrintException」
- loading / error / conflict 四态
- 设置页要显示**保存状态**（已保存/未保存/保存中/保存失败）
