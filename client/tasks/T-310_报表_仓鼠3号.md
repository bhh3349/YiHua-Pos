## 2. 老板要看什么

**餐饮老板每天就问三个问题**：
```
今天卖了多少？      → 营业额
卖得最好的是什么？→ 菜品排行
为什么比昨天少？→ 时段/渠道对比
```

报表不是给财务看专业报表，是给**不懂财务的老板**看的。所以要**直白**。

## 3. 功能要求

### 3.1 今日概览（默认页）

```
┌────────────────────────────────────────────┐
│  2026-10-12（今天）                        │
├────────────────────────────────────────────┤
│  营业额        ¥12,860.00    ↑ 8.2% 较昨日│
│  订单数            142 笔     ↑ 5.1% 较昨日│
│  客单价            ¥90.56                   │
│  优惠金额          ¥420.00                  │
│  实收            ¥12,440.00                 │
├────────────────────────────────────────────┤
│  堂食 ¥8,200  外带 ¥2,600  配送 ¥2,060      │
│  现金 ¥7,100  记账 ¥1,800  自定义 ¥3,540    │
└────────────────────────────────────────────┘
```

**要求**：
- 同比（较昨日）用**箭头 + 百分比**，涨绿跌红（国内习惯可用红涨绿跌，做成可配置）
- 支付方式分布要**能看出占比**
- 数据**离线也能看**（本地库查，不依赖服务端）

### 3.2 时段分析

**餐饮最重要的报表** —— 决定备货和排班。

```
     营业额
 ¥3000│                    ████
      │              ████  ████
 ¥2000│        ████  ████  ████
      │  ████  ████  ████
 ¥1000│  ████  ████
      │  ████  ████
    $0└────────────────────────
       6  9  12  15  18  21  24 时
```

- 按小时统计营业额
- **标注高峰时段**（客流量最高）
- 能按天/周/月切换
- 要能看**翻台率**（正餐）或**取号数**（快餐）—— 有就显示，没有就隐藏

### 3.3 菜品排行

```
1. 牛肉面      128 份   ¥2,304.00   占比 18%
2. 宫保鸡丁     96 份   ¥3,648.00   占比 28%
3. 珍珠奶茶     89 杯   ¥1,068.00   占比 8%
```

**要求**：
- 按**销售额**排（老板关心赚多少，不是卖多少份）
- 也能按**销量**排
- Top 20，可翻页
- **占比要显示**（直方条或百分比）
- 要能**下钻**：点某个菜看今天卖了多少、哪个时段卖的

### 3.4 桌台/包间使用（正餐）

```
A01  12 桌次  ¥3,200  平均 ¥267
A02   8 桌次  ¥1,600  平均 ¥200
包间01  4 桌次  ¥2,800  平均 ¥700  ← 客单价最高
```

- 按桌台/区域统计
- 要能看出**哪些桌台利用率低**（备菜和排班用）

### 3.5 交班/账实（与 T-309 联动）

```
班次   收银员  订单   应收     实点     差额
早班   张三    128   ¥8,600  ¥8,650   +50
晚班   李四     94   ¥4,260  ¥4,190   -70
```

- 只读
- **能点进去看该班的订单明细**

### 3.6 导出

**老板要发朋友圈/给合伙人看**：

```
[导出 CSV]  [导出 Excel]  [打印报表]
```

**要求**：
- 导出**当前筛选条件下的数据**（不是全量）
- CSV 要有 UTF-8 BOM（**Excel 打开中文不乱码** —— 这个细节很重要）
- 导出中文字段名（不是 OrderNo 这种）
- 导出失败给明确提示

### 3.7 日期范围

```
[今天] [昨天] [本周] [本月] [自定义范围]
```

- 自定义范围要有上限（如 90 天），超了提示
- 大范围查询要**分页/流式**，不能一次 load 十万行

## 4. 计算逻辑（**必须精确**）

```csharp
public class ReportCalculator
{
    decimal CalcTurnover(IReadOnlyList<Order> orders);        // 营业额
    decimal CalcAvgTicket(decimal turnover, int orderCount);  // 客单价
    decimal CalcDiscountTotal(...);                            // 优惠合计
    decimal CalcNetReceived(...);                             // 实收
    IReadOnlyList<HourBucket> BucketByHour(...);              // 时段分布
    IReadOnlyList<RankItem> RankProducts(...);                // 菜品排行
    IReadOnlyList<RankItem> RankDesks(...);                   // 桌台统计
    decimal CalcPayTypeShare(decimal part, decimal total);    // 占比
}
```

**必须明确的规则**（在报告里写清楚，并测）：

| 问题 | 规则 |
|---|---|
| 营业额算不算退菜 | 退了的要减 |
| 冲正单 | 负数单要不要计入 |
| 抹零 | 抹掉的部分算不算营业额 |
| 客单价分母 | 用订单数还是商品件数？ |
| 作废单（Void） | 一律排除 |
| 跨天订单 | 按下单时间还是结账时间归属？ |
| 占位/取整 | 显式 `MidpointRounding.AwayFromZero` |
| 占比分母为 0 | 返回 0，不返回 NaN/Infinity |

**特别要求**：占比计算**分母为 0 时必须返回 0**，不能抛异常或返回 NaN —— 这类边界在实际数据里很常见（今天还没开张）。

## 5. ⚠️ Domain 缺口（**不要自己改**）

`Order` 有 `AmountTotal`、`AmountDiscount`、`AmountPay`、`AmountRefund`、`SettleTime`、`OrderType`、`GuestCount`。

**缺的**：

| 缺口 | 用途 |
|---|---|
| 报表查询用的投影/聚合 DTO | 不建议在客户端 Domain 加，报表应走**服务端聚合接口** |
| `SalesReport` 服务端模型 | 服务端要有报表接口 |

**重要判断**：报表数据量大（长期累积），**不应该全量拉到客户端本地算**。

**处理方式**：
- **短期**：本地库（SQLite）聚合查询，只查日期范围内的，数据量可控
- **上报**：在报告里说明「长期需要服务端报表接口」，我统一安排 Hermes 做

**本期你做**：客户端本地 SQLite 聚合 + 查询接口抽象（`IReportDataSource`），预留切服务端的实现。

## 6. UI 工艺要求

必读 `client/tasks/T-005_控件库_仓鼠3号.md` 第 3 节。

**Craft Read 参考**：
- `CRAFT_LEVEL` 7 / `MOTION_INTENSITY` 2 / `VISUAL_DENSITY` 8 / `DESIGN_VARIANCE` 4

**关键要求**：
- **数字要能一眼读懂**，不要花哨
  - 主指标用 `AmountDisplay`（tabular-nums）
  - 同比涨跌用箭头 + 颜色，但**不要闪烁/动画**
- **占比用条形，不用饼图** —— 饼图在小屏难比较长度，条形能一眼看出大小
- 时段图用**简单条形**（Border 宽度），不要第三方图表库
- 表格**右对齐金额**、千分位分隔
- 排行要有**视觉焦点**：Top 3 加深色背景，其余正常
- 日期切换用**分段控件**（今天/昨天/本周/本月/自定义）
- 长列表要虚拟化
- 报表是**静态数据**，不要转场动画（老板要看清楚）
- loading / empty / error 必做
  - empty：比如「今天还没有订单」+ 说明什么时候有数据
  - error：要能重试
