## 0. ⚠️ 先看这一节：合规不是软件问题，但软件会踩到

《单用途商业预付卡管理办法（试行）》（2012 年商务部令第 9 号，2016 年修订，
**目前仍现行有效**）适用于餐饮业发卡企业。查证结论如下。

### 0.1 备案责任在**商家**，不在你的软件

```
备案主体  = 发卡企业（有营业执照的餐饮店），不是你
你的责任  = 提供功能，让商家能合规地记录和导出
```

**你不需要替商家备案，也不需要在软件里做备案流程。**

### 0.2 但这几条会直接影响你的软件设计

| 法规条款 | 要求 | 对软件的影响 |
|---|---|---|
| 第十八条 | 单张**记名卡限额 ≤ 5000 元**，不记名卡 ≤ 1000 元 | **充值金额上限要做校验**，默认 5000 |
| 第十九条 | **记名卡不得设有效期** | **会员不能设「有效期」字段** |
| 第二十一条 | 办理**退卡**须留存姓名、证件号、卡号、金额；余额 < 100 元可付现金 | 要有**退卡流程**和**身份留存** |
| 第十七条 | 记名卡**购卡需实名**并留存身份信息 5 年 | 会员要有**手机号**（小店最现实的实名方式） |
| 第二十五条 | 预收资金余额 ≤ 上年度主营业务收入 40% | 系统给个**预警**即可，不强制 |

> 全文：[单用途商业预付卡管理办法（试行）· 中国政府网](https://www.gov.cn/zhengce/2012-09/21/content_5712346.htm)
> 地方规定可能更严（如[上海市单用途预付消费卡管理实施办法](https://sww.sh.gov.cn/zwgkhsgwj/20260622/ac6d7cbb797249e9a09a7cca1d6b5f3f.html)），
> **建议在软件里放一个「合规提示」页**，让商家自己看当地要求。

### 0.3 本期明确**不做**

```
❌ 不做充值资金存管（那是商家的银行账户，不是软件的事）
❌ 不做在线开卡（需要实名核验，实体店扫码开卡已够）
❌ 不做「充值送」
```

**「充值送」不做。** 商家要送钱直接调整余额，填原因即可。

## 2. 功能要求

### 2.1 会员基础（**核心**）

```
开卡 / 查卡 / 改资料 / 挂失 / 停用 / 消费记录
```

**要求**：
- 开卡**手机号必填**（小店最现实的实名方式，也是去重依据）
- 手机号是**唯一标识**，一个手机号只能一张卡
- **手机号要脱敏显示**（`138****8000`）
- 要能**挂失**：挂失后卡还能查到消费记录
- **停用 ≠ 删除**：停用后历史消费记录必须保留（财务凭证）
- 要能**充值**（有上限校验，见下）

**会员号规则**：
```
手机号 + 生日？不行—— 生日会泄露身份信息
用「手机号 + 建卡序号」或纯数字卡号
```

### 2.2 会员价与折扣（**最高频**）

```
会员价（单品）/ 会员折扣（整单）/ 会员等级
```

**要求**：
- **单品会员价**：`Product.MemberPrice` 已有，结账时自动切换
  - 必须**明确显示**「会员价 ¥18（原价 ¥22）」，不能让客人自己发现
- **整单会员折扣**：可配（如会员全场 9 折）
- **折扣优先级要写清楚**：
  ```
  单品会员价 > 会员折扣 > 普通折扣 > 抹零
  ```
  顺序错了老板会算不清账
- **会员价与券不能叠加**，要用券就取消会员价
- 要能**临时关闭**会员价（活动结束）

> ⚠️ 取整显式 `MidpointRounding.AwayFromZero`，全程 decimal。

### 2.3 充值与余额调整

```
充值 / 调整余额 / 余额支付 / 退卡
```

**⚠️ 本期不做「充值送」「充1000送100」这类赠送活动。**
商家要送钱，直接用「调整余额」，填原因即可。

**充值**（简单版）：

- 输入金额 → 余额增加 → 记一笔流水
- **上限 5000 元**（法规：单张记名卡限额），超了拒绝
- 要能**可配置**（地方规定可能更严），但**默认 5000 且不能调高**
- **余额不能为负**

**调整余额**（**这个才是高频功能，比充值还常用**）：

```
客人投诉了 → 老板改余额 +10，填「客人投诉补偿」
员工点错了 → 老板改余额 -5，填「点单点错」
```

**要求**：
- **必须填原因**，原因用**选择列表**（赠送 / 补偿 / 纠错 / 其他），
  不让打字
- **可以加也可以减**
- 每次调整**记一笔流水**，含金额、原因、操作人、时间
- **调整后余额不能为负**
- 要能**查看某会员的全部余额流水**（为什么少了钱要能查清）

> **余额支付要有可打印凭证**。

### 2.4 退卡（**法规要求，不能省**）

```
退卡申请 → 退款 → 留痕
```

**要求**：
- 退卡要**留存**：姓名、证件号、卡号、退款金额、时间
- 余额 < 100 元可付现金；否则应退回**同名银行账户**
  - 小店现实做法：先现金退款 + 留存凭证，**软件要能记录**退款方式
- 退卡后**余额清零**，消费记录保留

### 2.5 优惠券（**比充值更实用**）

```
发券 / 用券 / 核销 / 有效期
```

**要求**：
- 券类型：**满减 / 折扣 / 代金 / 兑换**
- 满减要有**门槛**（满 100 减 20）
- 券要能**发到会员**（一人一张，避免重复领）
- 券核销**必须幂等**：同一张券不能重复用
- 要有**有效期**，过期自动失效
- **券和会员折扣二选一**（不能叠加）

> ⚠️ **本平台的团购券（T-601）在服务端已经有完整实现**。
> 本卡的「优惠券」是**商家自发的营销券**，与团购券是两回事，不要混在一起。

## 3. 逻辑要求（纯逻辑，重点测）

```csharp
public class MemberPriceCalculator
{
    // 折扣优先级：单品会员价 > 会员折扣 > 普通折扣 > 抹零
    DiscountResult Calc(Order order, Member? member, CashRule rule);

    // 会员价与券互斥
    bool CanApplyBoth(MemberDiscount memberDiscount, Coupon coupon);

    // 充值上限（法规：记名卡 5000）
    bool ValidateRecharge(decimal amount, decimal upperLimit, out string? error);

    // 余额调整：可加可减，但不能为负
    BalanceAdjustResult Adjust(MemberBalance balance, decimal delta, BalanceChangeReason reason);

    // 退卡
    RefundResult Refund(MemberBalance balance, MemberRefund req);
}

public class CouponValidator
{
    bool ValidateThreshold(decimal orderTotal, decimal threshold, out string? error);
    bool ValidateExpiry(DateTime expiry, DateTime now, out string? error);
    bool ValidateRedeemable(bool used, bool bound, long boundMemberId, long currentMemberId);
}
```

**必须覆盖的边界**：

| 场景 | 期望 |
|---|---|
| 手机号重复开卡 | 拒绝 |
| 手机号脱敏 | `138****8000` |
| 停用会员查历史 | **记录保留** |
| 会员价低于普通价 | 用会员价 |
| 会员价高于普通价 | **拒绝启用**（配置错误） |
| 会员折扣 + 普通折扣 | 按优先级，只用一个 |
| 会员折扣 + 券 | **互斥，不能叠加** |
| 充值 5001 元 | **拒绝**（超上限） |
| 充值 5000 元 | 允许 |
| **余额调整 +10** | 允许，记流水 |
| **余额调整 -5** | 允许，记流水 |
| **余额调整调到负数** | **拒绝** |
| **余额调整不填原因** | **拒绝提交** |
| 余额调整后可查全部流水 | 能查清每次变动 |
| 余额为 0 时支付 | 拒绝 |
| 余额支付扣成负数 | **拒绝** |
| 退卡余额 < 100 | 可现金退款 |
| 退卡余额 ≥ 100 | 需退款方式记录 |
| 券未达门槛 | 拒绝 |
| 券已过期 | 拒绝 |
| 券已核销 | 拒绝 |
| 券绑定他人 | 拒绝 |
| **同一张券重复核销** | **只成功一次** |
| 9.95 × 0.9 | 8.96（**AwayFromZero，不是 8.955→8.95**）|
