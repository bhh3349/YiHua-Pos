## 0. 先说清楚这**不是**什么

这张卡**不做进销存**。已经确认过：目标客户是单店小店，299 买断。

```
❌ 不做：入库 / 出库 / 盘点 / 报损 / 损耗统计 / 批次 / 保质期
❌ 不做：采购单 / 供应商 / 对账 / 多级分类
```

理由：30 平米的苍蝇馆子，老板早上数一下牛肉够不够，
晚上直接扔掉剩菜。**他不会打开电脑录「今日报损 3 斤，损耗 ¥78」。**
塞进销存进去只会让老板以为系统没用。

---

## 1. 为什么这个要做

**沽清 ≠ 进销存**。沽清是临时状态「今天这道菜卖完了」，小店天天用。

真实场景：

```
11:40 牛肉面卖完了，老板在出餐口贴张纸「牛肉面售罄」
12:30 服务员还在给客人下单，收银台直接出单 → 客人等 10 分钟被告知没有

线上更糟：
外卖平台上「牛肉面」还在卖，客人下单付款，
店里说卖完了 → 差评 + 平台扣分
```

**沽清的核心价值是「别再让客人白等」**，尤其是外卖平台上标沽清。

## 3. 功能要求

### 3.1 手动沽清（**核心**）

```
沽清某道菜 / 取消沽清 / 批量沽清
```

**要求**：
- **沽清后点单时该商品置灰 + 显示「已沽清」**
  ← 不能下单成功才报错
- 要能**批量沽清**（整个档口一键沽清），
  比一个个点快十倍
- 要能**按关键字批量沽清**（搜「面」，全沽清）
- 沽清/恢复都要**能打印**（贴在出餐口）

### 3.2 定时自动沽清（**外卖平台同步的前提**）

```
每天固定时间自动还原沽清
```

**要求**：
- 可配置时间（默认次日 09:00）
- **到点自动恢复供应**，不用老板手动清
- 要能**多时段自动沽清**（例如午市只卖午市菜，14:00 自动沽清晚餐菜）
- 定时逻辑要**可测**（注入时钟，不要写死 `DateTime.Now`）

> **这条直接关联外卖平台**：平台上「今日沽清」需要每天自动复位，
> 否则第二天开店全是沽清，平台显示卖完了，一单都没有。

### 3.3 外卖平台沽清同步（**接口预留**）

```
沽清 → 推送到外卖平台
恢复 → 推送到外卖平台
```

**要求**：
- 定义 `ISoldOutSync` 接口
- 本期只做 `self_platform`（自有平台）实现
- 美团/饿了么/抖音**只留骨架**，返回 `NotSupported`
- **业务代码不得出现 `if platform == "meituan"`** ← 与 T-405 同一条铁律，
  有 AST 测试保证

**接口先留着的理由**：你 99 元/平台/年卖的就是这个。
现在不做真对接，但**架构上不能堵死**。

## 4. 逻辑要求（纯逻辑，重点测）

```csharp
public class SoldOutCalculator
{
    // 是否可点单
    bool CanOrder(bool soldOut, out string? reason);

    // 批量沽清筛选
    List<int> FilterByCategory(List<Product> all, long categoryId);
    List<int> FilterByKeyword(List<Product> all, string keyword);

    // 定时还原：判断某个沽清记录是否该恢复
    bool ShouldRestore(SoldOutRecord record, DateTime now, TimeSpan dailyReset);

    // 多时段沽清：判断当前是否在沽清时段
    bool InSoldOutWindow(TimeSpan now, List<TimeRange> windows);
}

public class SoldOutService
{
    Task SellOutAsync(long productId, string operatorName);
    Task RestoreAsync(long productId);
    Task BatchSellOutAsync(IEnumerable<long> ids, string operatorName);
    Task ResetDailyAsync(DateTime now);          // 定时还原
    Task PushToPlatformsAsync(CancellationToken ct);
}
```

**必须覆盖的边界**：

| 场景 | 期望 |
|---|---|
| 已沽清商品点单 | 拒绝 + 「已沽清」 |
| 已沽清商品取消沽清 | 可点单 |
| 批量沽清按档口 | 只影响该档口 |
| 批量沽清按关键字 | 只影响匹配项 |
| 关键字无匹配 | **不报错，返回空** |
| 定时时间未到 | **不还原** |
| 定时时间到了 | 还原全部 |
| 手工沽清的记录 | **不被定时还原** ← 见下方说明 |
| 多时段：午市时段外 | 可点 |
| 多时段：午市时段内 | 沽清 |
| 未接入平台同步 | 返回 `NotSupported`，**不崩** |
| 平台同步失败 | 记录日志，**不阻塞本地沽清** |

**⚠️ 手工沽清 vs 定时沽清必须区分**：

```
老板手工沽清「今天这道菜没有」  → 明天 09:00 自动恢复
定时沽清「这张券只在午市用」    → 定时恢复
```

如果两者混在一起，会出现「老板手工沽清的菜第二天没人记得为什么不见了」。
**这条要在数据模型上分开，不要用一个 `IsSoldOut` 布尔搞定。**

## 5. UI 工艺要求

必读 `client/tasks/T-005_控件库_仓鼠3号.md` 第 3 节。

`CRAFT_LEVEL` 4 / `MOTION_INTENSITY 1` / `VISUAL_DENSITY 6` / `DESIGN_VARIANCE 2`

**关键要求**：
- **沽清列表要按档口分组**，老板按档口操作，不是按拼音
- 已沽清的项要**明显但克制**：置灰 + 「售罄」标签
  - **不要用鲜红色**（客人还看得见菜单，红色像报错）
  - 用**灰色 + 标签**
- 要有**大按钮**（后厨手上有油，小屏幕触控）
- 批量沽清要有**明确的确认范围**（「将沽清热菜档 8 道菜」）
- 定时设置要**说人话**（「每天 09:00 恢复供应」），不要「Reset Time: 09:00」
- 未接入平台显示「未接入」**并置灰**，不要让老板点了才知道
- 恢复供应要有一键「全部恢复」
- loading / empty / error 三态
- 不要转场动画
