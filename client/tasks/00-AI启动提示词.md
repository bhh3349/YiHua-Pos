4. client/src/YiHua.Pos.Domain/Entities/            实体定义（Order / Product / Desk）
5. client/src/YiHua.Pos.Domain/Interfaces/IRepositories.cs   你要实现的接口
6. client/src/YiHua.Pos.Domain/Enums/Enums.cs       枚举定义

**实体和接口已经冻结，你要实现接口，不要改定义。**

## 你的独占目录（只能改这两个）

client/src/YiHua.Pos.Data/
client/tests/YiHua.Pos.Tests/Data/

## 铁律

❌ 不修改 client/src/YiHua.Pos.Domain/**（只能读）
❌ 不碰其他模块的目录
❌ 不引入 SqlSugar 之外的 ORM
❌ 不直接推 main

## 核心设计（本地优先架构）

用户操作 → 先写本地 SQLite（权威数据源）→ 断网也能收银
         → 写 outbox 队列 → 联网后补传

关键点：
- SQLite 必须开 WAL 模式（PRAGMA journal_mode=WAL），断电保护
- Order.ClientOrderNo 必须建唯一索引（断网补传去重的基础）
- 下单（订单 + 明细 + 支付）必须在同一个事务里，失败全回滚
- 数据库路径跨平台：
    Windows: %LOCALAPPDATA%\YiHua\
    Linux:   ~/.local/share/YiHua/（若 /data 可写则优先 /data/）

## 交付要求

- ORM 用 SqlSugar（SqlSugarCore 5.1.4.207）
- net8.0 和 net6.0 都必须能编译
- 实现 IRepositories.cs 里的全部接口
- 含 xUnit 单元测试，用临时文件数据库，不污染真实数据

## 第三步：验证后推送

dotnet build client/YiHua.Pos.sln
dotnet test  client/YiHua.Pos.sln

git fetch origin && git rebase origin/main
git add -A

git push -u origin task/T-003-data

## 第四步：告诉 Lead

「T-003 完成，分支 task/T-003-data」
附：改动文件清单 + dotnet test 输出 + 数据库表结构说明（字段 + 索引）

# 冲突处理

| 情况 | 处理 |
|---|---|
| `git push` 被拒（非快进） | `git fetch origin && git rebase origin/main` 后重推 |
| rebase 有冲突 | **停下来**，把冲突文件告诉 Lead，不要自己瞎合并 |
| 发现自己改了别人的目录 | `git checkout origin/main -- <别人的文件>` 还原 |
