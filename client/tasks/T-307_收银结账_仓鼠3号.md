## 2. 业务背景：**现在不做线上支付**

**明确要求**（用户原话）：

> 「现在没有线上支付，接口预留」

所以本任务实现：

| 支付方式 | 状态 | 说明 |
|---|---|---|
| **现金** | ✅ 现在做 | 输入实收，算找零 |
| **记账** | ✅ 现在做 | 挂账，记到客户名下，后续结算 |
| **自定义收款（客人扫自己的码）** | ✅ 现在做 | **系统只记录**，钱直接进商家自己的账户 |
| 微信/支付宝（商户收款码） | 🔮 **接口预留** | 只定义接口和 UI 占位，不接 SDK |
| 微信/支付宝（商户号/API） | 🔮 **接口预留** | 同上 |

**「自定义收款」是这个模式的核心**：

```
客人扫商家自己的收款码 → 钱直接到商家账上 → 系统不知道收没收到
→ 收银员点「客人已扫码付款」→ 系统记一笔「自定义收款」
→ 对账时人工核对银行流水
```

所以自定义收款**不需要任何支付 SDK**，只需要记录金额 + 备注 + 凭据（可选照片/单号）。

```

│                                                  │
│  ① 整单折扣  [ 9 折 ]                   -7.40    │
```

**注意**：结账页和点单页**分离**。结账时收银员不该改商品（改了就乱了）。

## 4. 各支付方式要求

### 4.1 现金

```
点「现金」→ NumberPad 输入实收 → 自动算找零
  实收 ¥100 → 应付 ¥74 → 找零 ¥26
```

- 实收 < 应付 → 阻止，提示「实收不足」
- 快捷金额按钮（¥50/¥100/¥200/整单金额）
- **开钱箱**：`ICashDrawer.OpenAsync()`（T-106 已实现）
- 打印客显：显示「合计 / 实收 / 找零」（T-106 已实现 `ICustomerDisplay`）

### 4.2 记账（挂账）

```
选「记账」→ 选客户（或新建客户）→ 确认
```

- 需要客户档案：名称、联系人、电话、备注
- 支持「临时客户」（只有名字/电话）
- 记账订单进「未结账」列表，对账时处理
- **记账要有权限限制**：普通收银员能记账，但额度上限由店长设置
- 客户账目可查：历史消费、累计欠款

### 4.3 自定义收款

```
选「自定义收款」→ NumberPad 输入实收 → 备注（选填）→ 确认
```

- **不找零**（钱在客人手里，不找零就是实收=应收）
- 要记录：
  - 金额
  - 方式（微信/支付宝/银行卡/其他，选填）
  - 凭据号（选填，客人付款流水号）
  - 备注
  - 时间
- **凭据照片**（选填）：如果设备有摄像头，可以拍付款截图。这个**要接口预留**，不强制实现

### 4.4 线上支付（接口预留，不实现）

```
UI 上要有「微信支付」「支付宝」的入口
点进去 → 显示「暂未启用，请使用自定义收款」
```

**要求**：
- 定义 `IPaymentGateway` 接口（现在只有 `CustomQrPaymentGateway` 实现）
- 预留 `WechatPayGateway` / `AlipayGateway` 的接口骨架（**不实现业务**，或者实现但永远返回「未配置商户号」）
- 支付方式列表从配置读，新增方式时不用改 UI 代码

## 5. 折扣与抹零

```
整单折扣：
  方式A：按比例（9折 / 8.5折 / 自定义）
  方式B：直接减（减10元）
  方式C：抹零（直接抹掉分）

权限：仅店长
```

**取整规则**：显式用 `MidpointRounding.AwayFromZero`（收银不是银行家舍入）。

**抹零要显示出来**：收银员要能看到「原价 ¥74.57 → 应收 ¥74.50」，不能静默抹掉。

## 7. 结账后的选择

```
结账成功 → 
  [继续开台]  [打印小票]  [返回桌台]
  并提示「找零 ¥26」
```

- 小票打印失败 → 提示「结账成功但打印失败，点此重试」（**结账不能因为打印失败回滚**）
- 找零要**醒目标示**（大字号，这是收银员最容易出错的地方）

## 8. UI 工艺要求（硬性）

必读 `client/tasks/T-005_控件库_仓鼠3号.md` 第 3 节。

**Craft Read 参考**：
- `CRAFT_LEVEL` 8 / `MOTION_INTENSITY` 2 / `VISUAL_DENSITY` 6 / `DESIGN_VARIANCE` 3

**关键要求**：
- **应收金额要最大字号**（收银员的核心信息）
- **找零要更醒目**（大字号 + 强调色，全屏唯一 Primary）
- 支付方式是**大按钮**（≥56px），三个并列或一行三个
- 实收输入用 `NumberPad`（已有）
- 折扣/抹零入口**次要**（不占主视觉），但权限控制要严
- 结账按钮**足够大且位置固定**，要防重复点击（处理中状态）
- 打印失败**不能回滚结账**，要给出重试入口
- 8 态里的 **conflict** 必做：这桌已经被别人结账了 → 明确提示「本单已在其他设备结账」+ 返回桌台
- empty / loading / error 必做

**签名动作建议**：
**找零数字用强调色 + 轻微放大**，同时「原价/折扣/应收」用次级文字，形成一个清晰的视觉层级 —— 收银员一眼看到该给客人多少钱。
